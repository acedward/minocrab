#+title: Ledger hooks: the write program as a typed value

Decided with dmd, 2026-09-16. Follows notes/stream-design.org (M40/M41): the blind ops exist; this is how they are exposed to a programmer.

* The execution model, stated once

Two phases. At proving time the circuit runs on the witness and produces a proof and a TRANSCRIPT: a fixed list of Impact instructions with every constant baked in. At inclusion the ledger runs the transcript against the live state and lands the new state or fails the transaction. Nothing runs in the circuit at inclusion; nothing runs on the ledger at proving time. So the transcript is a function that runs after the circuit, on shared state, with the circuit's outputs as its arguments.

From the circuit's side the effects are APPLICATIVE: their structure never depends on any effect's result, because no effect has a result the circuit can see. A =popeq= is =assert(ledger.x == X)= with X a public input the prover supplied; the executor finds X by running the circuit against a state copy to a fixpoint. This is why every audit in the repo is static (leakage, contention, cost, disclosures). Inside the transcript the program is sequential (stack ops, =branch= on ledger values). The right name for the whole is optimistic concurrency control: the =popeq=s are the read set with assumed values, validated at commit; the writes are the write set, applied in emission order; the blind ops are commutative updates that bypass validation. Contention is read-set size on shared keys. Failure is atomic per transaction; =ckpt= splits a validated prefix from a fallible suffix and is in the backlog until it has its own design pass.

* The rule for the programmer

Inline is the read set; the hook is the write program. Anything inline that looks at the ledger is an assumption validated at landing and can go stale. Anything in the hook runs on whatever the ledger holds then, cannot go stale, and cannot tell the circuit anything. Blind reads and writes are therefore NOT offered inline (dmd: not easy to reason about); they live only in hooks.

* The two surfaces

Inline, as today: the typed ADT methods (=read=, =lookup=, =member=, =head=, the kernel reads), asserts on what came back, plain writes of circuit values. Every read is a =popeq=. =LedgerCell::combine_blind= and =snapshot_into= move OFF =LedgerCell= onto the hook builder.

The hook: =Hook<B>=, a closed typed program over ledger block =B=, taking public constants, attached with =c.then(hook)=. Emitted after the whole body whatever the position of the =then= call; several hooks run in attachment order (stated, since it is observable); a hook attached inside =c.when(g, …)= captures the guard at attachment and is emitted under it at finish, so it is absent from the transcript when g is off. A hook sees every inline effect of the body, including writes that appear textually after the =then=. The builder has no =popeq= method, so =Hook<B>: Blind= by construction; library APIs that need contention-freedom take a =Hook=.

#+begin_src rust
fn stamp(k: Handle<Public>) -> Hook<Block> {
    Hook::new()
        .add(&B.nonce, 1u64)                      // idxp; addi; insc
        .copy(&B.nonce, &B.nonce_at, &k)          // the snapshot
        .copy(&B.seen, &B.seen_at, &k)
}
#[circuit]
fn call(c: &mut Circuit3, pre: PreRecord) -> Discloses<(PreRecordFiled,)> {
    let k = pre.handle(c);
    let taken = B.bodies.member(c, &k);           // inline: a read-set entry, per key
    c.assert(not(is_true(taken)).message("already called"));
    B.bodies.insert(c, &k, &pre.entry());         // inline: a write of circuit values
    c.then(stamp(k));                             // hook: runs after, blind
    Discloses::of(())
}
#[circuit]
fn respond(c: &mut Circuit3, k: Handle, att: Attestation) -> Discloses<(HandleSettled, Height)> {
    let k = k.disclose_as::<HandleSettled>(c);
    let seen = B.seen_at.lookup(c, &k);           // Assumed<Uint<64, Public>>, stable (written once)
    let height = att.height.disclose_as::<Height>(c);
    c.assert(height.gt(seen).message("not after the call"));   // C3, inline
    B.bodies.remove(c, &k);
    B.seen_at.remove(c, &k);
    c.then(Hook::new().max(&B.seen, height));     // hook: blind max
    Discloses::of(())
}
#+end_src

Builder methods and when each fails the transaction (never on staleness):
| method | on chain | fails when |
|---|---|---|
| =add=, =sub=, =max=, =min=, =and=, =or= on a cell | read-modify-write, no popeq | overflow, underflow |
| =write(cell, v)=, =insert(map, k, v)=, =remove(map, k)= | the plain writes, as effects | never (remove of an absent key is a no-op) |
| =copy(src, dst[, key])=, =move_entry(map, from, to)= | slot to slot, the circuit never sees the value | absent source |
| =if_absent(map, k, ¦h¦ …)=, =if_below(cell, bound, ¦h¦ …)=, =if_unset(flag, ¦h¦ …)= | =branch= over a block; both arms typed to the same stack | inside the arm only |
| =then(other)= | concatenation | as its parts |
=First= stops being a special accumulator: =if_unset(flag, ¦h¦ h.write(cell, v).write(flag, true))=. No macro sugar for now (dmd: an expert tool; add =hook!= only if the builder becomes painful).

* What the types enforce

- Hook arguments are =Public= wires; a private value has no =push=. Disclose first.
- Cell arithmetic only on =Uint<≤64>= cells, booleans only on =Bool= cells, =copy= only between slots of one type, =insert= only of the map's value type: the existing =LedgerRepr= machinery.
- The stack: =Program<In, Out>= over type-level stack shapes (=State=, =Map<K,V>=, =Cell<T>=, =Key<K>=, =Bool=, =U64=), each op a method that exists only on the shapes it accepts; =branch=/=jmp= as =select(then, otherwise)= with both arms =S -> S'= and the skip counts computed (the milestone's Max off-by-one was a hand-counted skip). Strength as a marker: =push= is weak, =pushs=/arithmetic/=idx= are strong, =ins= requires strong (the compactc port's runtime failure becomes a compile error). Depth and reach bounds by missing impls at 16, as =KeyPath<11>=.
- =Hook<B>: Blind= always; no =popeq= method exists.
- Runtime, value-dependent, fails the transaction: absent key, overflow, underflow, array bounds, =concat= past the cell bound, gas.

* Stale values must be named (dmd, 2026-09-16: "make sure you have to explicitly use stale variables if possible")

Every inline read returns =Assumed<T>= instead of =T=. It behaves as =T= wherever the PROOF consumes it (asserts, comparisons, selects, arithmetic), so read-check-done code is unchanged. It has no =LedgerRepr= and no =push= into a hook, so re-entering the ledger — as a hook argument, as an inline write, as an inline insert — does not compile until the programmer writes =.stale()=, whose name is the record that the transaction assumes the value it read is still current at landing. The outbox never needs the word: it snapshots by blind =copy= instead of reading and writing back, which is the behaviour the type nudges toward.

Backstop: types track direct read results, not values derived from them (=c.add(seen.field(), 1)= is a bare wire). The circuit builder knows every wire's provenance (the leakage inventory computes it from the ZKIR), so the hook boundary checks it at build time and refuses a transcript-derived argument that did not pass through =.stale()=, naming the read it descends from. A BUILD-TIME error, not a compile error — the property is dataflow, which Rust's types do not carry without an effect system — and therefore the last rung of the house ladder, recorded here for dmd's review.

Churn: wrapping every read touches every ported contract. Reads feeding only asserts and arithmetic are untouched by construction; reads written back inline are exactly the stale-write sites. COUNT them when building and report the number; if large in the Compact ports, the fallback is the hook boundary by type first and inline stale writes as a lint. Not decided before measuring.

* What changes in what exists

=Stream='s primitive =insert= becomes inline body insert plus an attached hook; =Outbox::call= and =raise_seen= become the two circuits above; layouts unchanged. The ops in =minocrab-ledger= stay. Gate as M40: every builder method run through the executor on a seeded state; the two compile-fail classes (a private argument, an =Assumed= without =.stale()=) as doctests; the stream and outbox tests unchanged in what they assert.

* Backlog

=ckpt= (a commit point inside a transaction: what "fails" means changes; own design pass). Hook arguments derived from reads: allowed through =.stale()=; a first cut may forbid them outright if the backstop proves awkward.

* M42 A as built: the hook builder (2026-09-19)

Surface. =minocrab_std::v3::Hook= (=v3/hook.rs=): a closed program over the ledger, built by chaining =add= / =sub= / =max= / =min= / =and= / =or= (cells, =CellArith= = =Uint<8|16|32|64, Public>=; booleans on =Bool<Public>=), =write= / =insert= / =remove=, =copy(cell, map, key)= (the snapshot) / =copy_cell(src, dst)= / =move_entry(map, from, to)=, =if_absent(map, key, ¦h¦ …)= / =if_below(cell, bound, ¦h¦ …)= / =if_unset(flag, ¦h¦ …)=, and =then(other)=. Attached with =c.then(hook)= — an inherent method on =Circuit3= over a new =minocrab::v3::Deferred= trait, so the L2 crate knows "a program lowered at attachment and emitted after the body" and nothing about ledgers. Values enter through =HookValue<T>=: every =LedgerRepr= type (all =Public=), plus =u64= for any =Uint= cell and =bool= for a =Bool= cell, which become inline immediates (=.add(&B.nonce, 1u64)= names no wire). =Hook::into_ops(c)= lowers to the op list, public so a test can compare a hook against the explicit =minocrab_ledger= spelling.

Attachment semantics, all gated: lowered at =then= (wires are what they are at the call), emitted after the WHOLE body before the outputs (=entry_out= flushes right after the body; =finish= flushes as the backstop, so a hand-built circuit gets them too), in attachment order, each under the ambient guard captured at attachment (a hook inside =c.when(g, …)= is absent from the transcript where =g= is off — four fewer VM ops on the off path in the gate), refused at build time inside =when_private= as every on-chain effect is. =defer_impact= / =flush_deferred= live in =v3/effects.rs= because attachment reads the ambient stack, and that module is the one reader of it.

Ops added to =minocrab-ledger=: =cell_sub_at= (=idxp; push Δ; sub; insc=, checked — underflow fails the transaction), =cell_copy_at= (cell to cell, the snapshot's reach-back over =cell_write_at='s walk: =dup 2·len(dst)−1=), =map_move_entry_at=, and the named single ops =branch= / =jmp= / =member= / =lt= / =neg= / =pop= / =type_of= so the stdlib never spells an opcode. FINDING behind =move_entry=: the VM's =idx= of an ABSENT map key yields =Null= rather than failing (=vm.rs= =idx=: =unwrap_or(StateValue::Null)=), and =ins= stores that =Null= under the destination — so "absent source fails" needs a presence check the VM does not give for free. The one built is =dup 0; type; push 0; swap 0; sub; pop= after the fetch: =type= is 0 for a cell and 1 for =Null=, and =0 − type= is the checked subtraction that underflows exactly when the entry was absent. Six ops, total over every entry type (an =lt= or =eq= probe would decode the value and fail on wide ones). Gated both ways on the VM.

The branches: =<test>; branch len(arm); <arm>=, the test leaving TRUE when the arm is to be SKIPPED — =member= for =if_absent=, =lt; neg= for =if_below=, the flag itself for =if_unset=. The skip is the lowered arm's length, computed, never counted by hand; the arm is a =FnOnce(Hook) -> Hook=, so both sides of the branch leave the stack where they found it. =First= is =if_unset(flag, ¦h¦ h.write(cell, v).write(flag, true))=, the same five-to-nine ops =cell_write_first_at= emits.

DEVIATIONS from the design sketch, for dmd. (1) No =B= block parameter: =Hook= is not =Hook<B>=. The handles a hook takes (=LedgerCell<T>=, =LedgerMap<K, V, P>=) are not typed by the block they were declared in, so a block parameter on the hook would be a phantom that enforces nothing; adding block typing to every handle is a bigger change than this milestone and the wrong-block mistake has no way to happen in practice (a circuit's handles come from one derive). (2) No type-level stack. A declared field path is one to three elements AT RUNTIME (=FieldPath=), so the stack shape under =idxp f= is not a type and =Program<In, Out>= over stack shapes cannot be written against the existing paths without making the field-path length a type. What the types DO enforce is on the =Hook= surface: public arguments (a private wire is not a =HookValue= — compile-fail doctest), cell arithmetic on the VM's widths only (=CellArith=), booleans on =Bool= cells, =copy= only into a map of the cell's type, =insert= only of the map's value type, both arms of a branch hooks. The stack discipline of each lowering is the ledger crate's builders, gated byte-for-byte against the explicit op lists. (3) The reach bound is CONSERVATIVE at the type: =Reachable= is =FieldPath= and =KeyPath<1..=4>=, because the field half may be three elements and =dup='s nibble holds 15 (=2·(3 + 4) + 1 = 15=); a one-element field path could legally go two keys deeper and is refused anyway. The exact check stays as the builders' build-time assert. Compile-fail doctest: a =KeyPath<5>= destination.

Gate: =crates/minocrab-std/tests/v3_hook.rs=, 16 tests on the on-chain VM against a seeded six-field block — every method, each failure row of the table (overflow, underflow, absent source, failure inside an arm only when the arm runs), concatenation and attachment order, the after-the-body rule (an inline write textually AFTER the =then= lands first), =entry='s flush, guard capture, the =when_private= refusal, and a composite hook byte-identical to the explicit op lists. Every applied hook: zero reads, zero public transcript outputs. Both compile-fail doctests pass on the module.

* M42 B as built: =Assumed<T>= and the backstop (2026-09-19)

Surface. =minocrab_std::v3::Assumed<T>= (=v3/assumed.rs=): what EVERY inline read returns — =LedgerCell::read=, =LedgerMap::{lookup, member, size, is_empty}=, =LedgerSet::{member, size, is_empty}=, =LedgerList::{head, length, is_empty}=, =LedgerCounter::{read, less_than}=, both trees' =is_full= / =check_root=, =Primitive::{lookup, take}= (a tuple primitive's lookup is one =Assumed= over the tuple), =Stream::take= (a pair of them), and the kernel's =balance*= / =block_time*= / =unshielded_balance*=. NOT wrapped: =kernel::self_address= — a read of the contract's own address, which no transaction can change. =Copy= when =T= is, =Deref<Target = T>=, =Select= when =T= is (selecting between two assumptions is an assumption), =CheckOperand= (so =height.gt(seen)= and =eq(body, 120u64)= take it), =GuardCond= and =Assertion= and =Into<Bool>= / =Into<Check>= for =Assumed<Bool>= (so =c.when(found, …)=, =c.assert(found)= and =is_true(found)= take it — =is_true= now takes =impl Into<Bool<V>>=), =CircuitOut= when =T= is (a circuit may return what it read: the proof discloses the assumption). =map(f)= keeps the wrapper across a proof-side projection. The ONE way to a bare =T= for the ledger is =stale(self, c) -> T=; a bare =T= for the PROOF is =*x= (Copy) or a field through the deref, and the module docs say which is which.

=stale= takes =c=. The design wrote =.stale()=; the record has to live somewhere, and the circuit is where the reads are. What it records: every transcript read BEHIND the value's wires (=Circuit3::acknowledge_stale=, a backward walk over the instruction graph — =Builder3::transcript_reads_behind=), marked acknowledged. The wires come from a new =ProofWires= trait (=push_wires=), implemented for every leaf through =ledger_repr_via_abi!= (via =CallArg::push_call_slots=, no =c=), the two point types, tuples to four, =b32_newtype!= newtypes, and by =#[derive(LedgerRepr)]=; the contracts' hand-written =LedgerRepr= records (=Handle=, =PreRecord=, =QueueEntry=, =Commit=, =Owned=, =HandleOwned=, =EventRecordV2=, =Outstanding=) got hand-written =ProofWires= beside them. Not a blanket over =CallArg=: coherence would then forbid the tuple impls (upstream could add =CallArg= for tuples), so the list is explicit.

The backstop (=Circuit3::refuse_stale=). Where: hook arguments (every wire in a lowered hook, checked at =c.then=) and the VALUES of inline writes — =LedgerCell::write=, =LedgerMap::insert=, =LedgerList::push_front=, the trees' =insert= — through one =stored()= helper in =ledger.rs=. Map KEYS are exempt, deliberately: a key derived from a read (a request id hashed from the nonce) adds no assumption the nonce's own =popeq= does not already make, and every filing in the corpus keys by such an id. What it refuses: a wire with an unacknowledged =public_input= among its ancestors, naming the read — the ledger crate labels every minted read ("a cell read at field 3", "a map lookup at field 2 / key", "the kernel self read") via =Circuit3::label_reads=, and the message says =.stale(c)= or a hook. A build-time panic, the ladder's last rung, recorded for review: the property is dataflow.

Why =Deref=. Without it every field access on a read record (=view.commitment=, =env.amount_out=), every =.field()= / =.private()= / =.bytes()= on a read leaf, and every destructuring would need a spelling, which is most of the ported contracts. With it the type still refuses the DIRECT write-back (=M.write(c, &n)= is E0308 — compile-fail doctest on the module), and what the deref lets through (=&*n=, =n.field()=) is exactly the derived case the backstop exists for. So: the type is the nudge on the direct case, the backstop is the enforcement on every case, and =.stale(c)= is the one word that satisfies both.

THE COUNT (M42 B's measurement, 2026-09-19). The wrapper compiled against the whole workspace with 71 errors in the ported contracts and their tests; 27 were a circuit RETURNING a read (=Discloses::of(x)=), answered once by =CircuitOut for Assumed<T>= and =*x= at the site; the rest were by-value uses and destructurings, answered by =*x= (proof-side) or =.stale(c)= (ledger-side), the backstop deciding which by refusing at build time and naming the read. Sites that carry =.stale(c)= in the ported contracts: 41 — =erc20_vault.rs= 20 (7 =evm_chain_id=, 1 =caip2_id=, 1 =signet_request_nonce=, 11 EVM-address cells: =stata_token=, =stata_underlying=, =uniswap_router=, =vault_evm_address=), =erc20_vault_pending.rs= 10 (the callee-address reads and the calldata-address reads), =signet_flow.rs= 3 (=file_request='s nonce, =caip2_id=, =evm_chain_id=), =manager.rs= 6 (the shielded / unshielded balance read-modify-writes, debit and credit), =outbox.rs= 2 (the taken entry and the snapshot pair, re-stored under the request id). In the stdlib 3 (=Stream='s serial =combine= and =sequence=: the accumulator, and the head the staged state is computed from); in tests 5. OF THE 41, EIGHT ARE READ-MODIFY-WRITES (the request nonce ×2, the manager's balances ×6) — the contended pattern the word is for. THIRTY-THREE are CONFIGURATION cells (chain id, addresses, the caip2 id) read into a filed record: an assumption in the same sense, refused by the same backstop, but not contention anyone will hit — admin-set cells that change on a governance action.

THE DECISION (typed, as built; not a lint). The lint alternative would name the same 41 sites and could not tell the eight from the thirty-three either; the type says it at the value and the backstop closes the derived cases, which a lint over source text cannot see. What the count DOES argue for, as a follow-up for dmd: a =Config<T>= / sealed-cell kind whose reads are acknowledged at the read, as =kernel::self_address= already is (=never_stale=), which would take the thirty-three out and leave =.stale(c)= meaning exactly "contended". Not taken here: it needs a decision on what "sealed" means for the admin circuits that DO write those cells.

* M42 C as built: the port (2026-09-19)

=Primitive::combine_blind(c, acc, delta)= is =Primitive::combine(c, hook, acc, delta) -> Hook= and =snapshot(c, acc, snap, key)= is =snapshot(c, hook, acc, snap, key) -> Hook=: each APPENDS to a hook (=Add= → =hook.add=, =Max= → =hook.max=, …, =Last= → =hook.write=, =First= → =hook.if_unset(&written, ¦h¦ h.write(&value, Δ).write(&written, true))=, the snapshot → =hook.copy=), the tuple impls thread the hook through their components, and nothing is emitted until =c.then=. The delta and key limbs are lowered by the caller's =c= through a crate-private =Lowered= =HookValue=, so the =Primitive= impls need no =Clone= or ='static= on =S= or =K=. =LedgerCell::snapshot_into= and =combine_blind= are DELETED; =minocrab-ledger='s ops stay (=cell_write_first_at= is what =v3_blind='s explicit-list test still compares =First= against — byte-identical to the =if_unset= spelling, so the branch skip the builder computes is the one that was hand-counted). =Stream='s primitive =insert= is the inline member-check and body insert plus ONE attached hook (combine then snapshot, so the stored state is the post-step value as decided); =Stream::combine= on a primitive attaches the combine. =Outbox::call= and =raise_seen= go through those two and did not change; =emit= names its two stable reads with =.stale(c)= where they re-enter under the request id.

Gates unchanged in what they assert: =v3_blind= 13/13, =v3_stream= 3/3, =v3_vector= 9/9, =v3_hook= 16/16 on the VM; =evm_outbox= and =fee_ema= as before (the outbox's three circuits still read no accumulator cell; the transcript order is the same because the stream insert was already the last thing in =call=). The Monoid side is untouched (=Monoid::combine= on wires; the tuple impl now names =<P as Monoid<S>>::combine= to disambiguate from the hook one).
